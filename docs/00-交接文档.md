## 1. 一句话项目目标

把闭源的 Windows 局域网聊天软件**飞秋(FeiQ)** 做一个**安卓版**，让安卓手机能和电脑上的飞秋在同一 WiFi 下**互相发现、收发文字、传文件、传图片**。

**已经做到了。** 当前 App 在真机上和真飞秋实测通过：互相发现、文字双向、文件双向、图片双向（含飞秋私有内联图片协议）、消息持久化、微信风格 UI。

---

## 2. 最关键的认知（不懂这条会走弯路）

- 根目录的 `飞秋二次开发源代码及文档/` 是 **Windows COM 插件 SDK**，依赖 `FeiQ.exe` 进程，**和安卓毫无关系、不能移植**。不要试图用它。
- 真正的实现路线：飞秋 = **IPMsg(飞鸽传书)协议**的国产扩展版，UDP+TCP 端口 **2425**。安卓端 = **从零用 Kotlin 重新实现这套协议**，完全不碰飞秋的 exe。
- 飞秋在标准 IPMsg 之上有**私有扩展**（版本段、富文本标签、内联图片协议），这些**没有公开文档**，是靠**抓包逆向**出来的，全部记录在 `docs/01`。

## 4. 安卓代码结构（17 个 Kotlin 文件，~2000 行）

**net/ 协议层**
- `Protocol.kt` — 所有命令字/选项位常量(IPMSG_*)
- `PacketCodec.kt` — 报文编解码(`版本:包号:用户:主机:命令:附加段`)，GBK编码，飞秋版本段
- `UdpChannel.kt` — UDP收发(绑2425)，`sendNow`同步发(图片ACK用)，回调带srcPort
- `TcpFile.kt` — TCP文件传输：`TcpFileServer`(发文件)+`TcpFileClient`(收文件)
- `FileListCodec.kt` — 文件清单编解码(单/多文件)
- `InlineImageReceiver.kt` — ★飞秋私有内联图片重组器

**core/ 核心**
- `FeiqEngine.kt` — ★引擎核心(354行)：发现/收发消息/文件/图片/ACK，`onPacket`是总分发
- `FeiqService.kt` — 前台服务(保活+组播锁)
- `MessageRepository.kt` — ★常驻消息仓库(接收+持久化+通知+未读)，UI的数据源
- `MessageStore.kt` — JSON持久化(每对端一文件)
- `App.kt` — 全局单例(持有engine+repo)
- `Models.kt` — Peer/ChatMessage/IncomingFile
- `ChatRecord.kt` — 持久化消息项(文字/图片/文件)
- `NetworkInfo.kt` — 本机IP/广播地址/伪MAC/组播锁
- `Prefs.kt` — 昵称等偏好

**ui/ 界面**
- `MainActivity.kt` — 会话列表(头像/预览/未读/在线)
- `ChatActivity.kt` — 聊天(气泡/文件卡片/图片全屏)，`currentPeer`控制通知
- `UiUtil.kt` — 头像配色/时间/文件大小格式化

## 6. 怎么构建 & 测试（接手第一件事）

**环境**（这台笔记本已具备）：Android SDK 在 `C:\Users\13652\AppData\Local\Android\Sdk`，Gradle 9.1.0、AGP 8.13.1、Kotlin 2.2.20、build-tools 36.0.0。

**构建：**
```bash
cd android && ./gradlew.bat assembleDebug
# 产物: app/build/outputs/apk/debug/app-debug.apk
```

**装到手机(adb)：**
```bash
SDK=/c/Users/13652/AppData/Local/Android/Sdk
"$SDK/platform-tools/adb.exe" install -r android/app/build/outputs/apk/debug/app-debug.apk
```

**抓崩溃/调试日志：**
```bash
ADB="$SDK/platform-tools/adb.exe"
"$ADB" logcat -b crash -d                    # 崩溃堆栈
"$ADB" logcat -s FeiqEngine:I UdpChannel:I InlineImage:I  # 引擎日志
```

**联调铁律**（踩过的坑）：
- 飞秋和测试工具**不能在同一台机抢 2425 端口**。手机和电脑是不同设备，各自独立 2425，所以**手机↔电脑飞秋**是正确的联调方式。
- 改完代码**先自己 adb 装上确认不闪退**再交给用户测（吃过没验证就交付导致闪退的亏）。

## 7. 关键的逆向发现（省掉重新踩坑）

详见 `docs/01`，这里列最容易绊倒人的：

1. **飞秋版本段不是标准"1"**，而是 `1_lbt6_0#128#<MAC>#0#0#0#4001#9`。安卓要模仿（见 `PacketCodec.buildVersionField`）。
2. **编码是 GBK**（不是 UTF-8），除非带 UTF8OPT 标志。
3. **文件 GETFILEDATA 的 packetID 是十六进制**，安卓登记的是十进制，要 `toLong(16)` 转换匹配。
4. **飞秋富文本字体标签** `{/font;...;}` 要剥离。注意正则 `}` 在安卓ICU引擎**必须转义** `\}`，否则启动崩溃。
5. **内联图片是私有分块协议**：标记包`/~#>id<B~` + 分块包(cmd 0x2000C0) + **必须逐块回ACK**(cmd 0xC1, body`id|块号#`)否则飞秋卡死。ACK要同步立即发+发两遍防丢。

## 8. 已知问题 / 下一步可做

**已知问题（可接受）：**
- 首张大图(>64KB)首次接收会卡~15秒：诊断证明是**飞秋发送端在64KB边界单方面静默等待**，不是我们的bug(重复包=0)。小图和后续都秒到。根除需再逆向飞秋"窗口确认"格式。
- 多文件发送受手机系统文件选择器限制(有的不支持多选)。
- 直接 `am start ChatActivity` 会崩(引擎未初始化)，正常从主界面进不受影响。

**待开发(按价值排序)：**
1. **M4b 文件夹传输**(GETDIRFILES目录树) — 已做兼容实现：目录附件通告、GETDIRFILES层级流发送/接收、本地目录重建。
2. **正式签名APK** — 现在是debug包，要分发需签名打包。
3. **首张图15秒** — 再逆向飞秋窗口确认协议(用`/imgtest`钩子让安卓发>64KB图给飞秋抓包)。
4. 体验：夜间模式、自定义头像、消息搜索、电脑飞秋群聊（需抓包逆向）等。

**调试钩子：** 聊天框输入 `/imgtest` 会让安卓按飞秋协议发测试图给对端(用于抓飞秋的ACK/窗口确认)。
